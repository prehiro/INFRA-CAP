# INFRA-CAP Module Contract

Each feature in INFRA-CAP lives in its own package under `internal/modules/<name>/`
and implements the `web.Module` interface. This document is the contract every
module must follow so the host (`cmd/server`) can wire it up with one line and
so the templates, HTMX conventions, and audit/CSRF/error plumbing stay
consistent across the app.

If you're adding a new module, read this in full first. Existing modules
(`dashboard`, `licenses`, `audit`) are the reference implementations.

---

## 1. The `web.Module` interface

```go
// internal/web/module.go
type Module interface {
    Name() string
    RegisterRoutes(mux *http.ServeMux)
}
```

Two methods, period.

- `Name()` returns the short identifier used in log lines, the sidebar nav
  data, and the audit `Entity` column. It should be lowercase, no spaces, and
  stable across releases (changing it breaks existing audit-log queries).
- `RegisterRoutes(mux *http.ServeMux)` registers every HTTP route the module
  owns. Always use Go 1.22+ `mux.HandleFunc("METHOD /path", ...)` form
  (`GET /licenses/{id}/edit`, not `"/licenses/{id}"`). The `*http.ServeMux`
  passed in is the **protected** mux (already wrapped in the auth + CSRF
  middleware), so any route you register is automatically authenticated.

A module's `Module` type is just a value receiver holder, typically:

```go
type Module struct{ Store *Store }

func New(store *Store) *Module { return &Module{Store: store} }

func (m *Module) Name() string { return "licenses" }

func (m *Module) RegisterRoutes(mux *http.ServeMux) {
    mux.HandleFunc("GET /licenses", m.list)
    // ...
}
```

The `New(s *Store)` constructor keeps struct literals out of `main.go` and
makes wiring trivially testable (a module test can build its own `Module` with
a stub `Store`).

## 2. Per-module file layout

The established split is **two files per module**, plus a `templates/` mirror
that matches the host app's overall convention. Bigger modules may add more,
but the split is always:

```
internal/modules/<name>/
├── handlers.go   # HTTP layer: route funcs, request parsing, template calls, audit calls
├── store.go      # DB layer: SQL queries, struct models, filter/normalize logic
└── (optional)    # export.go, jobs.go, etc. — only when the module outgrows 2 files
```

Templates live in the **app-wide** template tree, NOT inside the module
package. This is deliberate: Go embed + `html/template` parses them as a
single set, and the `web.RenderNamed(w, r, "name_content", ...)` helper
expects every define to be globally addressable.

```
web/templates/pages/<name>.html          # source of truth
internal/web/templates/pages/<name>.html # embed mirror, regenerated by `make sync-templates`
```

If a module needs a partial shared across pages (e.g. a status pill,
empty-state), put it in `web/templates/partials/<name>.html` and remember to
add the `partials/*.html` glob to the `ParseFS` call in
`internal/web/render.go` — runtime panic otherwise. See the
"Shared partials" section below.

## 3. The Store / Handler split

**Store** owns the database. It exposes typed methods on a small `Filter`
struct, returns a slice + total count, and never touches the request or
response:

```go
// internal/modules/licenses/store.go
type Filter struct {
    Q         string
    Status    string
    Section   string
    Maker     string
    AssignedTo string
    Page      int
    PageSize  int
}

// normalize() runs in BOTH the handler AND the store. The handler calls
// it to get a clean value for the template (Page>0, etc.); the store calls
// it again on its own copy as a safety net. Bit us once: Page stuck at 0
// because the handler's value was passed by-value, so the store's mutate
// never reached the template's {{if eq .Page $.Page}} comparison.
func (f *Filter) normalize() { ... }

func (s *Store) List(ctx context.Context, f Filter) ([]License, int, error) {
    f.normalize()
    // build WHERE, run COUNT + SELECT, return
}

func (s *Store) Get(ctx context.Context, id int) (*License, error) { ... }
func (s *Store) Create(ctx context.Context, l *License) error     { ... }
func (s *Store) Update(ctx context.Context, l *License) error     { ... }
func (s *Store) Retired(ctx context.Context, id int) error         { ... }  // soft delete
```

**Handler** owns HTTP. It parses the request, calls the store, branches on
`isHTMX(r)` to pick the right template, and writes the response:

```go
func (m *Module) list(w http.ResponseWriter, r *http.Request) {
    f := buildFilter(r)  // r.URL.Query() -> Filter{...}
    f.normalize()         // see Store/Handler split note
    items, total, err := m.Store.List(r.Context(), f)
    if err != nil { http.Error(w, err.Error(), 500); return }

    // CRITICAL: dispatch on HTMX-Request header. The full-page wrapper
    // template contains the page header + filter bar + table — only use
    // that for a real browser navigation. HTMX refreshes must use the
    // fragment-only template or the page title + filter bar will
    // re-render inside the swap target ("title muncul 2×" bug).
    tpl := "<name>_content"
    if r.Header.Get("HX-Request") == "true" {
        tpl = "<name>_results_content"
    }
    web.RenderNamed(w, r, tpl, "<Page Title>", map[string]any{
        "Items":       items,
        "Total":       total,
        "Page":        f.Page,
        "TotalPages":  (total + f.PageSize - 1) / f.PageSize,
        "Filter":      f,
        // ... any other data the template needs
    })
}
```

## 4. Template defines convention

Every page template follows the same `define` naming scheme. The names
**must** be stable because Go embed + the `RenderNamed` helper both look
them up by literal string.

| Define name | Purpose | Rendered by |
|---|---|---|
| `<name>_content` | Full page (page header + filter bar + table). Returned on direct navigation. | `GET /<name>` from a browser address bar. |
| `<name>_results_content` | Fragment (table only, no header). Returned for HTMX swaps into the `#<name>-results` target. | `GET /<name>` with `HX-Request: true`, plus any `hx-get` that targets `#<name>-results` (pagination, live filter, etc). |
| `<name>_form_content` | Full-page form (New / Edit). Standalone, used as a no-JS fallback. | `GET /<name>/new`, `GET /<name>/{id}/edit` from a browser. |
| `<name>_modal_content` | Modal fragment (form inside an Alpine modal root). Returned for HTMX into `#modal-container`. | `GET /<name>/new`, `GET /<name>/{id}/edit` with `HX-Request: true`, plus the `{id}/retire-confirm` confirmation modal. |

The **fragment** templates are what `hx-target` lands inside:

- `#<name>-results` (e.g. `#license-results`, `#user-results`) is the swap
  target. The page wrapper uses the canonical two-layer pattern:

  ```html
  <!-- OUTER: swap target — no styling, just id + animation hook + flex sizing -->
  <div id="license-results" class="results-anim flex-1 min-h-0 flex flex-col">
    <!-- INNER: visual card — bg/border/rounded/shadow live here, gets swapped IN -->
    <div class="rounded-box bg-base-100 border border-base-300 shadow-sm overflow-auto flex-1 min-h-0">
      <table>...</table>
    </div>
  </div>
  ```

  Outer `id` is for HTMX. Inner div is for the visual card. **Never put
  styling on the outer** (double border, double `bg-base-100`, "canvas
  putih" bug). **Never duplicate the id** (one in the wrapper define, one
  in the fragment define) — only the wrapper owns it.

- `#modal-container` is the **app-wide** modal mount point. It's defined
  once in `web/templates/layouts/layout.html` (`<div id="modal-container"></div>`,
  right before `</body>`) and shared by every modal in the app. Modal
  templates render their own root inside the container.

## 5. HTMX modal pattern (View / New / Edit / Confirm)

Every modal uses the same Alpine root + HTMX retarget flow. Don't reinvent
it per module.

**Modal template shape** (`<name>_modal_content`):
```html
{{define "<name>_modal_content"}}
<div x-data="{
       open: true,
       close() { this.open = false; setTimeout(() => this.$refs.root.remove(), 220) }
     }"
     x-init="$nextTick(() => open = true)"
     @keydown.escape.window="close()"
     class="fixed inset-0 z-[90] flex items-center justify-center p-4">

  <div x-show="open" @click="close()"
       x-transition:enter="transition ease-out duration-200"
       x-transition:enter-start="opacity-0" x-transition:enter-end="opacity-100"
       x-transition:leave="transition ease-in duration-150"
       x-transition:leave-start="opacity-100" x-transition:leave-end="opacity-0"
       class="absolute inset-0 bg-black/50 backdrop-blur-sm">
  </div>

  <div x-ref="root" x-show="open"
       x-transition:enter="transition ease-[cubic-bezier(0.34,1.56,0.64,1)] duration-300"
       x-transition:enter-start="opacity-0 scale-90 translate-y-6"
       x-transition:enter-end="opacity-100 scale-100 translate-y-0"
       x-transition:leave="transition ease-in duration-200"
       x-transition:leave-start="opacity-100 scale-100"
       x-transition:leave-end="opacity-0 scale-95"
       class="relative w-full max-w-2xl max-h-[92vh] flex flex-col rounded-2xl bg-base-100 border border-base-300 shadow-2xl overflow-hidden">
    <!-- header, body, footer -->
  </div>
</div>
{{end}}
```

**Modal trigger** (anywhere in the page):
```html
<button hx-get="/<name>/new" hx-target="#modal-container" hx-swap="innerHTML">
  New <Name>
</button>
```

**Save handler** must return the refreshed list fragment AND set two HTMX
response headers, so the layout-level close-loop listener can detect the
"modal is done" event and close the modal + show the saved toast:

```go
w.Header().Set("HX-Retarget", "#<name>-results")
w.Header().Set("HX-Reswap",   "outerHTML")
web.RenderNamed(w, r, "<name>_results_content", "<Page Title>", data)
```

The close-loop listener lives in `web/templates/layouts/layout.html` (under
the `htmx:afterRequest` handler) and matches the `HX-Retarget` value to
know when to close a modal. If you forget those two headers, the modal
stays open after save and the user has to click backdrop or Escape to
dismiss it.

**Modal validation errors**: when a save POST fails validation, return the
modal fragment AGAIN (same template, with a `Form` field carrying the
submitted values and a `Errors` field) instead of closing. The layout
listener detects `.alert-error` inside the modal and keeps the modal open
so the user can fix the input. Successful saves use the retarget headers
above; failed saves don't, so the modal stays open automatically.

## 6. Audit logging

Every write operation (create / update / soft-delete / login) MUST call
`audit.Log(ctx, ...)` before the handler returns. Read operations do not
need an audit entry.

```go
import "infracap/internal/audit"

func (m *Module) save(w http.ResponseWriter, r *http.Request) {
    // ... parse, validate, store.Update ...
    if err != nil {
        audit.Log(r.Context(), m.DB, &audit.Entry{
            ActorID:  userIDFromSession(r),
            Action:   "license.update",
            Entity:   m.Name(),        // "licenses"
            EntityID: strPtr(strconv.Itoa(id)),
            Changes:  strPtr(changeSummary),
            IP:       strPtr(r.RemoteAddr),
        })
        // ... return updated list fragment ...
    }
}
```

`Entity` should always be the module's `Name()` so the audit page can
group by module. `EntityID` is the string form of the primary key (audit
table is generic across all modules). `Action` uses the convention
`<entity>.<verb>` (`license.create`, `license.update`, `license.retire`,
`user.toggle_active`, `login.success`, `login.failure`).

Audit failures are **logged but not returned to the user** — a missing
audit row should never break a save. Wrap the call in a recover-tolerant
helper if you want belt-and-suspenders.

## 7. CSRF

All non-GET routes are CSRF-protected by the global `web.CSRFValidate`
middleware. Two paths to pass the token:

- **HTMX (preferred)**: nothing to do. The layout has a global
  `htmx:configRequest` listener that copies the `infracap_csrf` cookie
  into the `X-CSRF-Token` request header on every request. As long as
  your form uses `<form hx-post="...">`, the header is set automatically.

- **Plain HTML form** (rare; only for non-modal direct-nav pages):
  include the token as a hidden field. The `RenderNamed` helper injects
  `csrfToken` into template data in BOTH the HTMX and full-page branches,
  so the same value is reachable from any template:

  ```html
  <form method="post" action="...">
    <input type="hidden" name="_csrf" value="{{.csrfToken}}">
    ...
  </form>
  ```

If a POST silently returns `403 CSRF token mismatch` even though the user
is logged in, first check whether the form is plain HTML — that's
the 99% case. The fix is the hidden field above.

## 8. Error handling

Handler error rules:

1. **Validation errors** (4xx-shaped, user-correctable): collect into
   `data["Errors"]` (a `map[string]string` of field → message), re-render
   the same modal form with `Form` pre-populated and `Errors` non-empty.
   The modal's `x-show` is on the Alpine root, so the user sees the
   `.alert-error` banner and the form re-rendered with their values.

2. **DB / unexpected errors** (5xx-shaped, not the user's fault): return
   a generic error page or a 500 with a clean message. The layout's
   `htmx:responseError` listener surfaces a top-center red toast with
   the status code and a Retry button. The handler should NOT echo
   the raw DB error to the user (it leaks schema details) — log it
   server-side, return a sanitized message.

3. **Auth errors**: handled by middleware, not by handlers. If your
   route is registered on the protected mux, you're done.

4. **`404 Not Found`**: if your handler can return "the row you
   requested doesn't exist" (e.g. `/licenses/{id}/edit` with a bad id),
   render a clean 404 page, not a raw `http.NotFound`. The audit page
   does this with a styled "Not found" card.

Don't write `panic` for recoverable errors — the global recover
middleware exists, but a clean error response is always better.

## 9. Registration (wiring it into the host)

`cmd/server/main.go` is the single place every module gets attached.
There are three sub-muxes:

- `mux` — public routes (login, logout, healthz, static files).
- `protected` — the auth + CSRF middleware wrapper. Anything registered
  here requires a valid session.
- `auditMux` — special sub-mux for the audit module, because audit
  routes live outside the `protected` mount path (see below).

A module's `RegisterRoutes` is called with whichever mux is appropriate.
The convention is:

```go
// cmd/server/main.go
import (
    "infracap/internal/modules/audit"
    "infracap/internal/modules/dashboard"
    "infracap/internal/modules/licenses"
    "infracap/internal/modules/notes"
    "infracap/internal/auth"
    // ...
)

authMod      := auth.New(&auth.Store{DB: database})  // auth has its own pattern
dash         := dashboard.New(dashboardStore)
licMod       := licenses.New(&licenses.Store{DB: database})
auditMod     := audit.New(&audit.Store{DB: database})
notesMod     := notes.New(&notes.Store{DB: database})

// auth routes go directly on mux (some are public, some need session, some need CSRF)
authMod.RegisterRoutes(mux)

// all UI modules go on `protected` (auth + CSRF already wrapped)
dash.RegisterRoutes(protected)
licMod.RegisterRoutes(protected)
notesMod.RegisterRoutes(protected)

// audit gets its own mux so it can be mounted in BOTH the user UI path
// and the internal audit log path. See audit module for the pattern.
auditMod.RegisterRoutes(auditMux)
```

To add a new module, the steps are:

1. Create `internal/modules/<name>/` with `handlers.go`, `store.go`.
2. Add the route templates in `web/templates/pages/<name>.html`.
3. Run `make sync-templates` to mirror them to the embed dir.
4. Add the import in `cmd/server/main.go`, build the module, call
   `RegisterRoutes(protected)`.
5. If the module needs sidebar navigation, add an entry to the
   `navItems` slice in `web/templates/layouts/layout.html` (the dashboard
   + users + licenses entries are the reference).

That's it. No central registry, no plugin discovery, no DI framework —
just packages and one line in `main.go`.

## 10. Conventions summary (checklist for code review)

When you finish a new module, run through this list:

- [ ] Module implements `web.Module` (`Name()`, `RegisterRoutes(mux)`).
- [ ] Constructor is `func New(s *Store) *Module`, not a public struct literal.
- [ ] `Store` is a struct with `DB *sql.DB` (or `*sqlx.DB`) and exported
      methods; no `net/http` types in the store.
- [ ] `Filter.normalize()` is called in BOTH the handler AND the store.
- [ ] All write paths call `audit.Log(...)` with `Entity: m.Name()`.
- [ ] HTMX-aware handlers dispatch on `r.Header.Get("HX-Request")` to
      pick between `<name>_content` and `<name>_results_content`.
- [ ] Modal save handlers set `HX-Retarget: #<name>-results` and
      `HX-Reswap: outerHTML` on success.
- [ ] Modal validation errors re-render the modal fragment with
      `Errors` populated (no retarget).
- [ ] Routes use Go 1.22+ `mux.HandleFunc("METHOD /path/{id}", ...)` form.
- [ ] All routes registered on the `protected` mux, not `mux` directly.
- [ ] No horizontal scroll on mobile — the responsive pattern (dual
      `<tr>` for desktop + card) is used on every list table.
- [ ] No `go:embed` or `os.Open` in module code — templates are loaded
      by the host from the embed FS.
- [ ] `make sync-templates && make css && go build` runs cleanly after
      the changes (no new classes missing from `app.css`).
- [ ] `go vet ./...` passes (handlers shouldn't have dead code or
      unreachable branches).
- [ ] A short test (`go test ./internal/modules/<name>/...`) covers the
      filter normalization edge cases (Page=0, PageSize=0, empty Q).
      Integration tests against the live DB are optional but encouraged
      for the license module's validation rules.

That's the contract. Existing modules follow it; new modules should too.
Deviations are fine if you have a good reason, but document them in this
README so the next person doesn't have to re-derive your reasoning.
